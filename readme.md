
#### Запуск
Из корневой:
dotnet run --project VyshKat.App
dotnet test VyshKat.Tests

При запуске сначала идет демо всех сценариев (приемка, отказ вследствие техосмотра (отрицательная энергия), вывод списка простых транспортов)

Затем запускается цикл для ручного ввода:
1. добавить самокат (электрический!)
2. добавить велосипед
3. добавить электровелосипед
4. добавить шлем
5. добавить док-станцию
6. добавить зарядный шкаф
7.вывести отчет (сколько транспорта, вещей, суммарное потребление квт)
8. список транспорта, подходящих новичкам
9. вывести имена + номера транспорта и вещей
0. выход


Тесты покрывают 90%

#### Структура проекта

VyshKat.App/
   Items/
   MainLogic/
   App.cs
   Program.cs
VyshKat.Tests/
    UnitTest1.cs

в Items лежат интерфейсы предметов (транспорта, вещей) и их классы
Основная логика, что использует эти классы реализована в MainLogic
в App.cs реализована логика консольного приложения (ввод, вывод, демо версия, вспомогательные функции для вывода). Данная логика была вытащена из Program.cs чтобы можно было покрытить итоговую работу приложения тестами

#### Логика решений
Информация про потребление энергии вынесена в отдельный интерфейс IEnergyConsumer. Его реализуют самокат, велосипед, станция и зарядный шкаф
Велосипед и шлем его не реализуют, у них нет в целом параметра затрат энергии

Все виды транспорта наследуются от класса Transport, который хранит имя, номер и простоту для новичка
Все виды предметов (шлем, станция) наследуются от Thing
Transport и Item реализуют интерфейс IInventoryItem

Все инвентарные номера выдает класс InventoryNumberGenerator, который хранит счетчик

Вся логика меню и вывода вынесена из Program в класс App. Ввод и вывод App получает через конструктор как TextReader и TextWriter (в приложении это Console.In и Console.Out, в тестах StringReader и StringWriter), что позволяет отдельно протестировать без консоли
При этом проверяется не конечный вывод в TextWriter (потому что текст вывода можно поменять без изменения логики), а корректность результата (что при добавлении транспорта он действительно добавляется, а не просто выводится сообщение о добавлении )

"Техосмотр" реализуется классом ServiceCenter, который проверяет только корректность входных данных (например, электропотребление не отрицательна, а простота в нужном диапазоне)
класс ServiceCenter реализует интерфейс IServiceCenter, и в случае необходимости проверки других условий, можно создать другой класс техосмотра что будет реализовывать данный интерфейс, или добавить проверку в сам класс ServiceCenter

Техосмотр проходят как транспорт, так и вещи
